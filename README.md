# 消息总结机器人

飞书群聊应用机器人，使用 Python SDK 长连接接收事件，调用兼容 **Anthropic Messages** 的模型服务。当前仅支持群聊，不处理私聊。

## 群内使用

1. 在群中通过「多选」挑选需要总结的消息。
2. 将所选消息「合并转发」到本群。
3. **引用回复这条合并转发记录**，使用飞书的 @ 功能选中本机器人，发送 **总结**、**帮我总结一下**或**总结重点**。
4. 机器人确认引用有效、记录可读取且长度未超限后，先回复「收到，正在处理」，再回复总结结果。

总结支持常见请求表达，例如 `总结`、`帮我总结一下`、`总结重点`、`请帮我总结一下这段聊天记录` 和 `总结要点`，也接受句尾的句号、感叹号。识别使用受限的请求语法，不通过模型猜测意图，也不会仅因为消息里出现“总结”两个字就执行功能；`不要总结`、`取消总结`、`总结功能怎么用`、无关请求、额外 @其他成员或附加附件/链接会显示文字功能菜单。

| 输入 | 行为 |
| --- | --- |
| 普通群消息，或仅 @其他成员 | 不响应 |
| 引用合并转发记录并发送「@机器人 帮我总结一下」等总结请求 | 材料校验通过后先回执，再总结这份记录 |
| 发送总结请求但没有引用，或引用普通单条消息 | 直接给出正确操作步骤，不发送处理回执 |
| @机器人后发送未识别的指令，或仅 @机器人 | 直接显示群内文字功能菜单，不发送处理回执 |
| 引用记录无法读取，或所选记录过长 | 直接说明读取失败或提示调整记录，不发送处理回执 |
| 私聊，或其他机器人的消息 | 不响应 |

只有被 @ 才启动功能。合并转发本身不触发总结；不会猜测“最近一条转发”，也不读取近期 N 条群消息作为总结兜底。起止消息、按时间范围总结、自动群聊总结均不作为本版入口。

总结限于所选材料，时间范围前使用 `【时间】`，栏目标题使用 `【讨论主题】`、`【关键结论】`、`【待办事项】` 和 `【待确认问题】`。图片、语音、视频、文件、卡片及嵌套合并转发只保留类型/文件名占位；已撤回的子消息标注无法读取，不下载或识别附件。当前只展开用户引用记录的直接子消息，不递归展开嵌套转发。

## 发言者名称与长度边界

名称优先取消息接口返回的 `sender_name`，缺失时尝试从本群成员的 `name` 获取；仍不可得时明确显示「姓名未知」，不猜测、不编号。名称缓存在内存中按群隔离，成功查询最多缓存五分钟，查询失败短时缓存，避免逐条重复请求。

**目前不能保证独立群昵称优先。**飞书已核实的公开群成员结构仅提供 `name`（名字），没有明确的独立群昵称字段；`sender_name` 也未被官方定义为群昵称。本版使用服务端可取得的显示姓名，不将个人别名或账号姓名冒充群昵称。

总结不受旧的 `HISTORY_MAX_MESSAGES`、`HISTORY_HOURS` 配置约束。所选记录会完整传入模型；超过单条或总字符预算时，明确提示拆分/缩短，不静默丢弃较早消息或截断正文。模型达到输出上限时，结果附带未完整生成的提示。

## 飞书应用配置

在 [飞书开发者后台](https://open.feishu.cn/app) 创建企业自建应用，开启机器人能力，配置机器人名称并加入目标群。代码不会远程修改机器人名称。

申请并发布生效所需的**应用身份**权限：

| 权限 | 用途 |
| --- | --- |
| `im:message.group_msg` | 读取群内被引用的合并转发记录及其子消息 |
| `im:message:readonly` | 调用获取指定消息的内容接口 |
| `im:message:send_as_bot` | 在原群引用回复回执、菜单、操作提示和总结 |
| `im:chat.members:read` | 可选；消息没有姓名时读取群成员显示姓名 |

已有 `im:message` 等权限时，可按官方接口说明替代相应读取/发送权限。只订阅 @消息事件不能替代读取合并转发记录所需的群消息权限。开通读取权限不代表普通群消息会触发功能，业务层始终精确过滤本机器人的 @。

在「事件与回调」中选择 **使用长连接接收事件**，添加 **接收消息 v2.0**（`im.message.receive_v1`）。如控制台要求检测连接，先启动下述程序，再保存事件配置。发布版本，使机器人能力、事件和权限生效；确保机器人有群内发言权限、测试用户位于应用可用范围内。

## 安装、配置与启动

需要 Python **3.10+**。进入本目录后执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows PowerShell 可使用 `py -3 -m venv .venv`，随后用 `.\.venv\Scripts\python.exe` 替代下文的 `python`，无需修改脚本执行策略。

首次使用且没有实际配置文件时，将 `.env.example` 复制为 `.env`。已有配置请保留，不要覆盖。填写：

```dotenv
FEISHU_APP_ID=你的飞书应用ID
FEISHU_APP_SECRET=你的飞书应用密钥
LLM_BASE_URL=你的Anthropic兼容服务地址
LLM_API_KEY=你的模型服务密钥
LLM_MODEL=服务实际支持的模型名称
```

`LLM_BASE_URL` 支持域名根地址、以 `/v1` 结尾的地址或完整 `/v1/messages` 地址，也支持代理前缀路径。模型名称必须是所用服务实际支持的模型 ID。

```bash
python main.py --check-config
python main.py
```

第一条只验证本地配置格式，不连接飞书、不调用模型、不创建任务数据库。第二条启动服务并保持长连接；启动日志不等于飞书已鉴权成功。`BOT_OPEN_ID` 留空时，正式启动会自动查询本机器人身份；填入时必须是机器人的 `ou_...` ID，不能填 `cli_...` App ID。

停止服务使用 **Ctrl+C**，程序会等待在途请求结束。修改配置后需重启。程序固定读取本项目的 `.env`；已有进程环境变量优先，相对数据库路径也以本目录为基准。已有 `.env` 中的 `TRIGGER_MODE=all` 会兼容读取并强制按 `mention` 处理，无需为取消全群触发修改实际配置。

使用当前环境也可直接运行 `.venv/bin/python main.py`，不必激活虚拟环境。不要同时启动多个共用同一数据库的服务进程。

## 可选配置

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TRIGGER_MODE` | `mention` | 固定仅 @触发；旧值 `all` 不再开启全群触发 |
| `BOT_OPEN_ID` | 空 | 正式启动时自动获取，或手动指定当前机器人 `ou_...` ID |
| `ALLOWED_CHAT_IDS` | 空 | 群白名单，多个 ID 以英文逗号分隔；空表示所有已加入群 |
| `MAX_INPUT_CHARS` | `24000` | 全部所选记录 JSON 字符预算，含转义膨胀 |
| `MAX_MESSAGE_CHARS` | `2000` | 单条正文字符上限，超限须缩短单条文字或调整配置 |
| `LLM_MAX_TOKENS` | `2048` | 模型输出 token 上限 |
| `LLM_TIMEOUT_SECONDS` | `90` | 模型请求超时 |
| `LLM_MAX_RETRIES` | `2` | 网络错误、429/5xx 的额外重试次数 |
| `DISPLAY_TIMEZONE` | `Asia/Shanghai` | 总结时间范围使用的时区 |
| `STATE_DB_PATH` | `data/bot.sqlite3` | 持久化任务与去重数据库 |
| `JOB_MAX_RETRIES` | `5` | 队列每阶段首次尝试之外的额外重试次数；`0` 表示不自动重试 |
| `JOB_RETRY_BASE_SECONDS` | `5` | 队列指数退避初始间隔（秒），至少 `0.1` |
| `JOB_RETRY_MAX_SECONDS` | `300` | 队列退避间隔上限（秒），不得小于初始间隔 |
| `LOG_LEVEL` | `INFO` | 业务日志级别 |

旧 `HISTORY_*` 参数仅供保留的历史网关兼容方法使用，新的总结流程不调用该方法，也不启用起止消息模式。

## 回执、恢复与去重

- 事件回调只过滤和落盘，不等待模型；独立预处理线程先识别总结请求表达，再校验引用记录、可读内容和输入长度。**仅通过这些检查的总结请求**会收到「收到，正在处理」，自然表达和简短指令遵守同一套校验。
- 菜单、操作提示、读取失败及超长提示直接回复，不发送处理回执。前一条模型总结耗时较长时，后续菜单仍可直接回复，后续有效总结也可先收到回执。
- 有效总结的回执成功并保存状态后，模型线程才调用模型。校验通过的材料缓存在内存中供模型线程复用；重启丢失缓存时重新读取材料。回执发送失败时不开始模型调用，任务按退避间隔自动重试，无需重启。
- 使用**发起请求的消息 ID** 对重复事件去重；两条不同的请求即使引用同一份聊天记录，也会分别调用模型，不按被引用记录 ID 缓存总结。回执与最终结果的 UUID 分开，网络重试和重启继续使用相同阶段的 UUID。飞书的服务端去重窗口有限，超过窗口后恢复仍可能产生重复回复。
- 最终文本先保存再发送，**同一请求**发送失败后自动重试并复用已保存结果，不重复调用模型；已保存的菜单或操作提示直接重发，不补发处理回执。完成后清空持久化正文与回复，仅保留去重状态；已完成记录保留七天。若模型已返回，但结果还未成功保存时进程中断，恢复仍可能重新调用模型。
- 队列将执行次数和下次重试时间保存在数据库中。每阶段默认最多额外重试五次，等待间隔依次为 **5、10、20、40、80 秒**；调整次数后，间隔按指数增长并以 `JOB_RETRY_MAX_SECONDS` 封顶。等待退避不占用工作线程，其他到期任务可继续处理。回执成功后重置次数，结果发送使用独立的重试预算。
- 重启继续遵守已保存的次数和下次重试时间；进程中断时已领取的执行也计入次数，在剩余预算内退避恢复。达到上限后任务保留为 `failed`，记录错误日志，重启不会重新开启重试预算；调低上限后，已超出新预算的待重试任务也会停止。旧库首次升级会补充重试字段，将未过期的旧失败任务纳入重试。更早版本中没有保存 @依据和指令的未完成任务仍保留为 `legacy`，不自动发送旧总结；请按新操作重新提交。
- 重试耗尽后，机器人会引用原请求通知用户“本次请求处理或回复失败，自动重试次数已用完”，并提示稍后重新发送或联系管理员。通知有独立的持久化状态和发送 UUID，不覆盖已保存的总结、不重新调用模型；通知发送失败也按 `JOB_*` 策略独立退避重试。重启会恢复未完成通知，已送达或已耗尽的通知不会重新发送。飞书接口持续不可用时，通知也可能无法送达，耗尽后会记录错误日志。
- 升级时会为七天保留期内、尚无通知状态的失败任务安排通知。仍待发送或发送中的通知不会被七天清理提前删除；通知送达或耗尽后，失败记录仍按七天保留策略清理。
- 队列重试适用于回执、最终结果发送失败及未预期的执行异常。读取记录或模型调用失败仍按现有策略生成用户提示，提示本身发送失败时才进入队列重试。`LLM_MAX_RETRIES` 和飞书网关内部重试控制一次执行中的网络请求，与队列重试分别生效，实际网络尝试次数可能叠加。
- 日志不输出正文、姓名或密钥。待处理/失败任务仍保存恢复所需的触发消息和结果；内存中读取的合并转发内容不写入队列表。

## 扩展功能

在 `summary_bot/routing.py` 的 `COMMANDS` 登记关键词、功能说明和用法，再在 `SummaryBot._handlers` 注册对应处理函数，并为需要耗时处理的功能添加输入校验。功能关键词先精确匹配；总结另外登记受限请求语法，其他功能不会自动采用总结的自然表达规则。文字菜单使用同一份注册表生成，不通过模型猜测功能。新增功能沿用群 @过滤和结果持久化流程；当前只有通过校验的总结请求发送处理回执，菜单与错误提示直接回复。

## 离线验证

```bash
python -m unittest discover -s tests -v
```

全部使用虚构凭据、临时数据库、模拟飞书请求和 HTTPX MockTransport，不读取 `.env`，不访问真实群聊或模型。覆盖总结请求表达、拒绝误触发、引用关联、所选消息完整性、非文字占位、名称降级、跨群隔离、独立回执、去重、旧库迁移、重启恢复、队列重试与退避配置、失败通知、独立请求与发送重试的区别和真实 SDK 请求格式。

离线测试不能替代实际飞书权限和客户端操作验证。真实验证可按“普通群消息无回复 → @帮助仅显示菜单 → 引用普通消息发送‘帮我总结一下’仅提示用法 → 引用有效合并转发并发送‘总结重点’，先收到回执再收到结果”的顺序检查；总结结果应包含带 `【】` 的时间及栏目标题。
